# Спецификация пакета рендеринга

## Назначение и зависимости

`render.go` преобразует layout-дерево в строки терминального содержимого, вычисляет размеры split/flex, нормализует и обрабатывает ANSI-содержимое и предоставляет точки входа для сбора границ. Геометрия layout и список его границ формируются `newLayout` из `layout.go`; сбор `BorderHit` выполняет `collectLayoutBorders`.

Файл использует типы пакета (`Node`, `SplitConfig`, `FlexConfig`, `FlexItem`, `Direction`, `Bounds`, `layoutNode` и др.), `MinPanelSize`, стили границ/схлопывания и пакеты `github.com/charmbracelet/x/ansi`, `github.com/charmbracelet/x/ansi/parser` и `github.com/rivo/uniseg`.

## Рендеринг layout

- `renderNode(node, w, h)` создаёт layout с размерами `max(0,w)` × `max(0,h)` и возвращает результат `renderLayout`.
- `renderLayout` создаёт контекст рендеринга. Если layout равен `nil` или его высота не положительна, результат — `nil`. Пустой узел и узел без распознанного типа заполняются пустыми строками. Для leaf без панели или с неположительной шириной также используются пустые строки; иначе `Panel.View(w,h)` обрабатывается через `padContent`.
- `renderContext` кэширует пустые строки по ширине и высоте, вертикальные границы по состоянию dragging, горизонтальные границы по ширине и состоянию dragging, а также строку границы схлопывания. Кэш действует только в рамках контекста.
- Внутренний `renderResult` несёт строки и признак `shared`, который используется split-рендерером для выбора/создания среза строк.
- `renderSplitLayout` при числе детей меньше двух возвращает пустые строки. Он рендерит первых двух детей; видимость границы определяется наличием элементов в `layout.borders`. Для `Vertical` содержимое соединяется построчно, а при видимой границе между ним ставится вертикальная граница. Если `OnCollapse != nil` и `CollapseRow >= 0`, на этой строке вместо неё выводится стилизованный `<`. Для `Horizontal` добавляется горизонтальная граница между строками детей, только если граница видима. Остальные дети не используются. Конкретное число строк зависит от результатов детей и способа их объединения.
- `renderFlexLayout` при отсутствии конфигурации или детей возвращает пустые строки. Видимые разделители определяются индексами `layout.borders` (поле `FlexIndex`). Для направления `Horizontal` строки детей соединяются вертикальными границами; для `Vertical` группы строк соединяются горизонтальными границами. Используются все дети. Границы зависят от `Dragging`.
- `renderVerticalSplit`, `renderHorizontalSplit` и `renderFlex` создают соответствующий `Node` и делегируют `renderNode`. `renderFlexRow` и `renderFlexColumn` игнорируют аргумент с размерами и делегируют `renderFlex`.
- `lineAt(lines, index)` безопасно возвращает пустую строку, если индекс вне диапазона.
- `renderBlankLines(w,h)` возвращает `nil` при `h <= 0`; иначе создаёт `h` строк шириной `max(0,w)`: пробелы при положительной ширине, пустые строки при нулевой.
- `renderVerticalBorder` выбирает обычный стиль или стиль dragging для символа `│`; `renderHorizontalBorder` делает то же для строки из `width` символов `─`, возвращая пустую строку при `width <= 0`. Обе границы обрамляются `ansi.ResetStyle`. Граница схлопывания — `<`, также обрамлённый сбросом стиля.

## Вычисление размеров

### `computeFlexSizes(avail, items)`

Пустой `items` даёт `nil`, отрицательный `avail` заменяется нулём. База схлопнутого элемента равна 1; он не участвует в распределении добавочного места. База остальных элементов — положительный `Basis` или `MinPanelSize`. При `avail == 0` возвращается срез нулевых размеров. Если сумма баз больше `avail`, пространство распределяется пропорционально базам. Иначе назначаются целочисленные базовые размеры, а оставшееся пространство отдаётся несхлопнутым элементам пропорционально положительным `Grow`; если их сумма не положительна, применяются равные веса. Остаток целочисленного распределения получает последний участвующий элемент. Распределение не выполняется при неположительном количестве пространства/весов либо нечисловой или бесконечной сумме весов.

`distributeFlexBases` распределяет величину пропорционально базам; `distributeFlexGrow` — по весам роста либо равномерно, исключая схлопнутые элементы. Доли округляются вниз, последний участвующий элемент получает остаток. Отрицательная доля ограничивается нулём, а доля не может превышать оставшуюся величину.

### `computeSplitSizes`

Отрицательное доступное место заменяется нулём. Базовый размер схлопнутого элемента — не меньше 1 и не больше `avail`. Если схлопнут один элемент, другой при `avail >= MinPanelSize+1` сохраняет минимум `MinPanelSize`; если схлопнуты оба, первый получает ограниченный размер, второй — остаток. Для обычного split NaN-доля заменяется на 0.5, доля ограничивается диапазоном [0,1]. Первый размер — `int(avail*fraction)`; при `avail >= 2*MinPanelSize` он ограничивается диапазоном `[MinPanelSize, avail-MinPanelSize]`, иначе — `[0,avail]`. Второй размер составляет остаток.

## Нормализация и обработка строк

- `padVisualLine` при неположительной ширине возвращает пустую строку. Иначе она обрезает содержимое по визуальной ширине через `truncateTerminalFragment`/`ansi.Truncate`, измеряет результат `ansi.StringWidth` и дополняет пробелами до заданной ширины.
- `normalizeTerminalText` заменяет некорректные UTF-8 последовательности на `�`. Управляющие символы табуляции, CR и LF заменяются пробелом; ESC и BEL сохраняются для обработки ANSI, прочие управляющие символы удаляются.
- `sanitizeFrameworkLabel` возвращает строку без изменений, если это валидный UTF-8 без ESC и управляющих символов; иначе нормализует её и удаляет ANSI-последовательности через `ansi.Strip`.
- `sanitizeTerminalFragment` нормализует текст и, если в нём есть ESC, удаляет неполный ANSI-хвост, если он обнаружен.
- `truncateTerminalFragment` нормализует, обрезает через `ansi.Truncate` с указанным хвостом и санитизирует результат.
- `ansiEndsInGroundState` сообщает, что нормализованная строка завершается в состоянии Ground ANSI-парсера.
- `incompleteANSITailStart` проходит по байтам с таблицей переходов ANSI-парсера и распознаёт границу незавершённого управляющего хвоста; при обычном завершении возвращает `-1`.
- `padContent(content,w,h)` при неположительной ширине или высоте делегирует `makeEmptyLines`. Иначе разбивает содержимое по `\n`, возвращает ровно `h` строк; отсутствующие и пустые строки заменяются строкой из `w` пробелов. Остальные строки визуально усекаются/дополняются до `w`. Каждая строка получает завершающий `ansi.ResetStyle`.
- `makeEmptyLines` возвращает `nil`, если ширина или высота неположительны; иначе возвращает `h` строк по `w` пробелов.
- `emptyView(height)` возвращает пустую строку при `height <= 0`, иначе строку из `height-1` переводов строки.

## Границы

`BorderHit` содержит указатели на `SplitConfig`/`FlexConfig`, направление, координаты `X`/`Y`, длину, `Bounds` и `FlexIndex`; значения заполняет layout-сборщик. `findBorders(node,x,y,w,h)` создаёт layout с исходными координатами и размерами `max(0,w)` × `max(0,h)` и возвращает `collectLayoutBorders(layout)`. `findFlexBorders` аналогичен, создавая временный узел с Flex. Геометрия, фильтрация скрытых границ и обход дочерних узлов реализованы layout-кодом.

## Побочные эффекты

Функции формируют строки и срезы и вызывают layout-функции и `Panel.View`; прямого I/O и изменения глобального состояния нет.
