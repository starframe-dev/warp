# Перетаскивание границ — спецификация

## Назначение

`drag.go` не содержит реализации. Перетаскивание границ split/flex обрабатывается в `tab.go`, а геометрия вычисляется общим layout-деревом из `layout.go`.

## Hit-testing

- Перед обработкой события мыши `Tab` вычисляет актуальный layout для области содержимого вкладки.
- Список `BorderHit` строится из того же layout, который используется рендерером.
- Координаты мыши переводятся из экрана в координаты содержимого с учётом позиции таббара.
- Границы проверяются в терминальных ячейках и только в пределах содержащего прямоугольника.
- Клик по скрытой границе между схлопнутыми областями не начинает drag.

## Перетаскивание

- Нажатие на границе сохраняет split или flex и индекс flex-разделителя.
- При движении доля split рассчитывается по координате относительно области-владельца границы.
- Размеры flex пересчитываются с использованием текущей геометрии контейнера.
- Во время перетаскивания обновляются геометрия и `ResizeMsg` дочерних панелей.
- Событие отпускания сбрасывает состояние перетаскивания.

## Общее правило

Рендеринг, hit-testing, `Elements`, размеры `ResizeMsg` и drag используют один layout-контракт. Нельзя независимо пересчитывать размеры в обработчике мыши: это приводит к несовпадающим видимым и кликабельным границам.
