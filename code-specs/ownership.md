# Спецификация `ownership.go`

## Назначение

Файл пакета `warp` реализует внутренний учет владения панелями. Он связывает дерево панелей с объектом `panelOwnership`, находит панели, которые остаются в дереве или были удалены из него, предотвращает повторную обработку одной и той же панели и вызывает `Unmount` для действительно удаленных панелей. Экспортируемых объявлений в файле нет; типы и функции предназначены для внутреннего использования пакетом.

## Типы и состояние

- `panelOwnership` хранит корневую `Panel` в поле `root` и `sync.RWMutex` в поле `mu`. Блокировка защищает чтение и замену ссылки на корень.
- `panelInstanceKey` представляет идентичность экземпляра панели. Ключ включает динамический тип `reflect.Type` и либо адрес указателя (`address`), либо само значение `Panel` (`value`) для сравнимых типов-значений.
- `panelInstanceCollector` накапливает найденные панели в `panels` и использует `visited` для предотвращения повторного обхода поддерживаемых составных панелей.

## Функции и методы

### Управление корнем владения

- `newPanelOwnership(root Panel) *panelOwnership` создает объект владения с указанной корневой панелью.
- `(*panelOwnership).setRoot(root Panel)` безопасно заменяет корень под эксклюзивной блокировкой. Для nil-получателя ничего не делает.
- `(*panelOwnership).rootPanel() Panel` безопасно возвращает корень под блокировкой чтения. Для nil-получателя возвращает nil.
- `(*panelOwnership).unmountRemoved(candidates []Panel)` сравнивает кандидатов с текущим деревом корня. Для каждого уникального кандидата, которого больше нет среди принадлежащих корню экземпляров, вызывает `Unmount()`, если панель реализует `Unmounter`, затем отсоединяет связь владения для поддерживаемых типов. Nil-получатель и пустой список не требуют действий. Nil/неидентифицируемые панели пропускаются, повторные кандидаты обрабатываются один раз. Панели, всё еще достижимые от корня, не размонтируются и не отсоединяются.

### Связь панели с владением

- `detachPanelOwnership(panel Panel, ownership *panelOwnership)` снимает связь только при совпадении текущего владельца с переданным объектом. Для `*TabGroup` и `*Tab` поле `ownership` обнуляется. Для `*warpPanel` операция выполняется под блокировкой `warp.mu`; при совпадении обнуляется `warp.ownership`, а `warp.ownsDomainRoot` устанавливается в `true`. Если внутренний `warp` равен nil или владелец не совпал, состояние не меняется. Остальные реализации `Panel` не обрабатываются.
- `attachPanelOwnership(root Panel, ownership *panelOwnership)` ничего не делает при nil-владельце. Иначе обходит дерево и назначает владельца `TabGroup`, `Tab` и связанным `warpPanel`. Для каждой группы также назначает ее `parent` всем ненулевым вкладкам. Для `warpPanel` поля владения и `ownsDomainRoot=false` обновляются под блокировкой `warp.mu`.
- `(*Tab).ensureOwnership() *panelOwnership` для nil-получателя возвращает nil. Если владение уже задано, возвращает его без создания нового. Иначе наследует владение родительской группы (предварительно вызывая `parent.ensureOwnership()`), либо создает владение с самой вкладкой в качестве корня, затем присоединяет к нему панели вкладки. Возвращает полученное владение.
- `(*TabGroup).ensureOwnership() *panelOwnership` для nil-получателя возвращает nil. Если владения нет, создает его с группой в качестве корня и присоединяет дерево группы; иначе сохраняет имеющееся. Возвращает владельца.

### Идентичность экземпляров

- `panelInstance(panel Panel) (panelInstanceKey, bool)` возвращает ключ и `true` для ненулевой панели, если динамический тип является указателем либо сравнимым типом. Для nil-панели и несравнимого неуказательного значения возвращает нулевой ключ и `false`. Для указателей идентичность задается динамическим типом вместе с адресом; для сравнимых значений — динамическим типом вместе со значением.
- `tabContainsPanel(tab *Tab, target Panel) bool` возвращает `false`, если `target` не имеет ключа экземпляра; иначе собирает панели вкладки и проверяет равенство ключей.

### Обход дерева

- `newPanelInstanceCollector() *panelInstanceCollector` создает сборщик с пустым списком и инициализированным множеством посещенных панелей.
- `collectPanelInstances(root Panel) []Panel` возвращает панели, достижимые от корневой панели.
- `collectNodePanelInstances(root *Node) []Panel` возвращает панели, достижимые из узла дерева.
- `(*panelInstanceCollector).visitNode(node *Node)` игнорирует nil. Посещает панель узла, обе ветви `Split` и узлы элементов `Flex`, пропуская nil-элементы.
- `(*panelInstanceCollector).visitPanel(panel Panel)` игнорирует nil-панели (с учетом `isNilPanel`). Для `*TabGroup`, `*Tab`, `*Scrollable`, `*Selectable`, `*Collapsible` и `*warpPanel` сначала предотвращает повторный обход по указателю, добавляет объект в результат и рекурсивно обходит его вложенное содержимое: вкладки группы; корень и панели float-окон вкладки; `Content` оберток; корень внутреннего `warp` для `warpPanel`, если он есть. Ненулевые float-элементы обходятся. Для других реализаций `Panel` панель добавляется в результат напрямую; для таких типов обход вложенности не выполняется.
- `collectTabPanels(tab *Tab) []Panel` является вспомогательной оберткой над сбором панелей вкладки.

### Вспомогательная операция со срезом

`removeSliceAt[T any](items []T, index int) []T` удаляет элемент по индексу с сохранением порядка. При индексе вне диапазона возвращает исходный срез без изменений. При удалении сдвигает последующие элементы влево, обнуляет последний слот и возвращает срез на элемент короче.

## Существенные детали реализации и ограничения

- Владение структурой корня синхронизировано через `RWMutex`; обход самого графа панелей и изменения полей `Tab`/`TabGroup` этой блокировкой не защищаются. Для `warpPanel` изменения полей внутреннего `warp` защищены его собственной блокировкой.
- Отслеживание посещенных составных панелей использует `map[Panel]struct{}` и предназначено для типов указателей, перечисленных в `visitPanel`. Произвольные пользовательские значения `Panel` добавляются в результат без дедупликации и рекурсивного обхода.
- Проверка сохранения/удаления опирается на идентичность экземпляра, а не на равенство содержимого панели. Повторные одинаковые по идентичности кандидаты в `unmountRemoved` вызывают размонтирование не более одного раза за вызов.
- Обработка жизненного цикла для удаления применяется только к `Unmounter`; отсутствие этого интерфейса не препятствует снятию внутренней связи владения для поддерживаемых типов.
- Файл использует `reflect` для динамического типа, сравнимости и адреса указателя, а также `sync` для блокировки корня и состояния `warp`.
