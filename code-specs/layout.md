# Геометрия раскладки — спецификация

## Назначение

`layout.go` вычисляет единое дерево границ панелей для заданного узла и прямоугольника. Одна геометрия используется при рендеринге, построении `Elements`, поиске панели под курсором, hit-testing границ, рассылке `ResizeMsg` и перетаскивании.

## Координаты

- `layoutRect` хранит начало `x/y` и размеры `w/h` в терминальных ячейках.
- Размеры нормализуются к неотрицательным значениям.
- Прямоугольники используют полуоткрытые интервалы: `[x, x+w)` и `[y, y+h)`.
- Граница split/flex занимает одну ячейку только когда оба соседних элемента развёрнуты и для неё есть место.
- `BorderHit` хранит абсолютную позицию границы, её длину, содержащий прямоугольник, направление и ссылку на split/flex-конфигурацию. Для flex также хранится индекс границы.

## Распределение размеров

- Split вычитает видимую границу из доступной оси до распределения.
- Flex учитывает только границы между соседними не свёрнутыми элементами, помещающиеся в доступной оси.
- При тесном viewport минимальные пожелания панели могут быть невыполнимы; размеры остаются неотрицательными, а суммарная геометрия не выходит за доступный прямоугольник.
- Свёрнутые элементы используют размеры, заданные их конфигурацией; скрытая граница между свёрнутой и развёрнутой сторонами не резервируется.

## Использование геометрии

- Рендерер размещает границы между дочерними областями, не пересчитывая размеры независимо.
- `Elements` смещает координаты дочерних элементов на начало их layout-области.
- `findLayoutPanel` и `Tab.handleMouse` используют те же полуоткрытые прямоугольники.
- `ResizeMsg` получает ширину и высоту листовой области.
- Перетаскивание пересчитывает долю относительно содержащей границу области, а не корневого окна.

## Ограничения

Текстовая ширина измеряется отдельно ANSI-aware функциями. Все координаты layout и событий мыши задаются в ячейках терминала; байтовая длина строки не является геометрической величиной.
