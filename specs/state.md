# Состояние и поток сообщений

## Модель Bubble Tea

Warp реализует `tea.Model`. `Init` не запускает команд. `Update(msg)` сохраняет размеры из `tea.WindowSizeMsg`, передаёт сообщение текущему корню и возвращает его `tea.Cmd`; `View()` рендерит корень с последними размерами. Встроенный Warp через `AsPanel()` синхронизирует локальные размеры с переданными размерами и проксирует Update.

Layout отправляет дочерним панелям `ResizeMsg{Width, Height}` при изменении выделенной области. Компоненты обрабатывают Bubble Tea, resize и пользовательские сообщения самостоятельно; прикладная логика обычно должна изменять своё состояние в Update и строить представление из текущего состояния в View.

## Где хранится состояние

- `Warp`: root, окно, revisions inspector, HTTP/lifecycle состояние.
- `TabGroup`: список вкладок, активный индекс, позиция/геометрия таббара.
- `Tab`: layout, активный focus, floats, границы и активное состояние drag, локальный viewport.
- Компоненты: только их предметное UI-состояние (например, `Input.Value`, `Scrollable.Offset`, `Selectable.Selection`, open/collapsed state).
- `FloatPane`: геометрия, preferred size и состояние drag/close.

Общие глобальные mutable store, подписки и event bus не являются частью модели. Панель может хранить собственное прикладное состояние и возвращать команды Bubble Tea для асинхронной работы.

## Маршрутизация

Сообщение проходит от Warp к корню. TabGroup обрабатывает tab shortcuts и таббар, а активный Tab проверяет события overlays и layout-границ до передачи пользовательской панели. Неактивным вкладкам могут рассылаться resize/framework/custom сообщения согласно типу события; клавиатурное взаимодействие ориентировано на активную/сфокусированную панель. Точные детали конкретных компонентов описаны в их code-spec.

Фокус — состояние, а не системный биндинг: приложение само решает, какое сообщение вызывает `FocusNext/Prev/First/Panel`. Переключение вкладок временно снимает/восстанавливает фокус; это не удаление и не вызывает `Unmount`.

## Временная геометрия

Tab хранит текущие drag-указатели split/flex и hit-зоны последних измерений; изменения layout сбрасывают устаревшие зоны. Float хранит собственный drag offset. Рендер/размер окна обновляет геометрию; mouse hit-testing должен использовать layout актуального события, не устаревшие координаты.

## Inspector snapshot

При активном HTTP inspector изменения состояния помечаются revisions, по которым строится immutable semantic snapshot. Построение не требуется, когда inspector отключён. `SemanticStableMsg` — явное обещание, что конкретное сообщение не меняет semantic state; оно позволяет отложить пересборку до следующего View. JSON представление кодируется лениво один раз на snapshot. HTTP-поток читает опубликованный снимок, но не является каналом обратной доставки событий в приложение.

## Удаление и освобождение

Снятие фокуса, переключение вкладок, сворачивание и временное скрытие сохраняют компонент и его состояние. При постоянном detach контейнер проверяет оставшиеся ссылки в домене владения и вызывает optional `Unmounter` только для окончательно удалённых экземпляров. Эта операция не заменяет явное закрытие прикладных ресурсов до установки панели в Warp.
