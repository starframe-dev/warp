render.go - Движок рендеринга Warp

Обзор

Пакет render обеспечивает функциональность рендеринга для терминального мультиплексора Warp. Он обрабатывает преобразование дерева узлов, представляющего макет интерфейса, в строки текста, которые можно отобразить в терминале.

Система рендеринга поддерживает:

  • Leaf узлы - Панели со зрением (рендеринг осуществляется через их метод View)
  • Распределённые макеты - Вертикальные и горизонтальные разбиения между панелями
  • Flex макеты - Взвешенные макеты типа flexbox с несколькими детьми
  • Свёрнутые панели - Панели, которые можно свернуть до фиксированного размера
  • Состояния перетаскивания - Визуальная обратная связь при перетаскивании границ между панелями

Рендеринг выполняется полностью в памяти и возвращает двумерный срез строк, представляющих буфер терминала, при этом каждая строка правильно стилизована с помощью последовательностей ANSI.

Публичный API

renderNode

func renderNode(node *Node, w, h int) []string

Основная точка входа для рендеринга дерева узлов. Принимает корневой узел и размеры (ширина и высота в символах), возвращает срез строк, представляющих рендеренный вывод.

Поведение:

  • Если узел nil, возвращает пустые строки, соответствующие размерам
  • Если узел лист (имеет Panel), вызывает его метод View и дополняет содержимое
  • Если узел имеет Split, делегирует renderVerticalSplit или renderHorizontalSplit
  • Если узел имеет Flex, делегирует renderFlex

findBorders

func findBorders(node *Node, x, y, w, h int) []BorderHit

Рекурсивно собирает все позиции перетаскиваемых границ из дерева узлов. Возвращает срез BorderHit, описывающий каждую границу с её позицией и конфигурацией Split или Flex, которой она принадлежит.

Применение: Используется для определения, какие границы можно захватить для разбиения/переконфигурации панелей.

padContent

func padContent(content string, w, h int) []string

Обеспечивает, чтобы содержимое имело именно w×h размер, дополняя пробелами и обрезая с помощью ansi.Truncate. Каждая строка заканчивается сбросом стиля ANSI, чтобы предотвратить утечку стиля между панелями.

Типы

BorderHit

type BorderHit struct {
    Split     *SplitConfig
    Flex      *FlexConfig
    Direction Direction
    X, Y      int
    Length    int
}

Описывает перетаскиваемую границу на заданной позиции в буфере терминала.

Поле Тип Описание
Split *SplitConfig Указатель на SplitConfig, владеющий этой границей (для макетов split)
Flex *FlexConfig Указатель на FlexConfig, владеющий этой границей (для макетов flex)
Direction Direction Направление границы (Vertical или Horizontal)
X, Y int Начальная позиция границы в координатах терминала
Length int Длина границы в ячейках

Внутренние функции

renderVerticalSplit

func renderVerticalSplit(split *SplitConfig, w, h int) []string

Рендерит макет вертикального разбиения. Рендерит первого и второго детей рядом с вертикальной границей между ними.

Ключевые детали реализации:

  • Вычисляет доступную ширину с учётом границы
  • Использует computeSplitSizes для распределения пространства между первым и вторым детьми
  • Когда либо из детей свернут, пропускает границу, чтобы панели сидели плотно
  • Использует разные символы границ для обычного и состояния перетаскивания

renderHorizontalSplit

func renderHorizontalSplit(split *SplitConfig, w, h int) []string

Рендерит макет горизонтального разбиения. Рендерит первого и второго детей один над другим с горизонтальной границей между ними.

Ключевые детали реализации:

  • Вычисляет доступную высоту с учётом границы
  • Использует computeSplitSizes для распределения пространства между первым и вторым детьми
  • Когда либо из детей свернут, пропускает границу
  • Границы рисуются как горизонтальные линии с помощью strings.Repeat

renderFlex

func renderFlex(flex *FlexConfig, w, h int) []string

Рендерит макет flex с взвешенными детьми. Поддерживает оба направления flex (row) и (column).

Ключевые детали реализации:

  • Вычисляет границы между flex элементами (на один меньше чем элементов)
  • Использует computeFlexSizes для определения размера каждого элемента
  • Для горизонтального flex: рендерит элементы в строке с вертикальными границами
  • Для вертикального flex: рендерит элементы в столбце с горизонтальными границами

computeFlexSizes

func computeFlexSizes(avail int, items []*FlexItem) []int

Вычисляет распределение размера для flex элементов. Реализует алгоритм типичного размерения flexbox который:

  1. Сначала распределляет базовый размер (1 для свернутых элементов, item.Basis или MinPanelSize для несвёрнутых)
  2. Вычисляет оставшееся пространство после распределения базового размера
  3. Распределяет оставшееся пространство по grow весам среди несвёрнутых элементов
  4. Если общий grow равен 0, распределяет поровну среди несвёрнутых элементов
  5. Распределяет оставшиеся пиксели на последний несвёрнутый элемент

computeSplitSizes

func computeSplitSizes(avail int, fraction float64, firstCollapsed, secondCollapsed bool, firstSize, secondSize int) (first, second int)

Вычисляет размеры для двух детей разбиения. Обрабатывает свернутые панели, используя их фиксированный свернутый размер.

Поведение:

  • Если первый child свернут: распределяет firstSize (минимум 1), второй получает оставшееся пространство
  • Если второй child свернут: распределяет secondSize (минимум 1), первый получает оставшееся пространство
  • В противном случае: делит по fraction, обеспечивая минимальные размеры панелей

makeEmptyLines

func makeEmptyLines(w, h int) []string

Создаёт двумерный срез пустых строк с заданными размерами. Возвращает nil если w или h <= 0.

Детали реализации

Обработка ANSI стилей

Весь рендеринг использует пакет charmbracelet/x/ansi для обработки ANSI стилей. Ключевые паттерны:

  • Символы границ обернуты в ansi.ResetStyle, чтобы предотвратить утечку стилей
  • padContent добавляет ansi.ResetStyle в конце каждой строки
  • Обрезка использует ansi.Truncate, которая сохраняет UTF-8 и последовательности ANSI

Обработка свернутых панелей

Когда панель свернута:

  • Граница между панелями пропускается, чтобы панели сидели плотно
  • Свёрнутые панели используют их фиксированный CollapsedSize вместо вычисленного размера
  • Это применимо как для split, так и для flex макетов

Состояние перетаскивания границ

Когда граница перетаскивается (split.Dragging или flex.Dragging истинно):

  • Используются другие символы границ/стили
  • borderDragStyle используется вместо borderStyle

Координатная система

Рендеринг использует нулевые координаты терминала:

  • X - позиция колонки (0 до width-1)
  • Y - позиция строки (0 до height-1)
  • Границы позиционируются относительно содержащей области

MinPanelSize

Константа, представляющая минимальный размер панели. Используется для обеспечения того, чтобы панели не становились слишком маленькими при вычислении размеров split/flex.

Пример

// Пример: Рендеринг простого вертикального разбиения
lines := renderNode(rootNode, 80, 24)
// lines - это []string, представляющих буфер терминала
for _, line := range lines {
    fmt.Println(line)
}

// Пример: Найти все перетаскиваемые границы
borders := findBorders(rootNode, 0, 0, 80, 24)
for _, border := range borders {
    fmt.Printf("Border at (%d, %d), length %d\n", border.X, border.Y, border.Length)
}
