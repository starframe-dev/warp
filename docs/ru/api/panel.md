# panel.go

Файл `panel.go` определяет абстракцию `Panel`, используемую в
TUI-фреймворке Warp. **Panel** — это базовая единица контента для
панелей Warp: может представлять что угодно — от обычного текста до
интерактивной графики и форм. Файл также содержит `BasePanel` — базовый
тип-заглушка для удобного встраивания.

## Публичный API

### Panel (интерфейс)

` type Panel interface { View(width, height int) string Update(msg tea.Msg) tea.Cmd } `

`Panel` — это основной интерфейс, который реализуют пользователи для
отображения контента внутри панелей Warp. Он содержит два метода:

| Метод | Описание |
|----|----|
| `View(width, height int) string` | Отображает содержимое панели для заданных размеров. |
| `Update(msg tea.Msg) tea.Cmd` | Обрабатывает входящие сообщения Bubbletea (клавиши, мышь и т.д.) при фокусе на панели. |

### Необязательный ContentHeightProvider

```go
type ContentHeightProvider interface {
    ContentHeight(width int) (height int, known bool)
}
```

Этот необязательный интерфейс сообщает intrinsic-высоту контента для
заданной ширины. `known == false` означает, что высоту нельзя надёжно
определить; provider не должен рендерить содержимое для её оценки.
Потребители трактуют отрицательную известную высоту как 0. Интерфейс
`Panel` не меняется, поэтому существующие реализации совместимы.
Известная intrinsic-высота обеспечивает точную ограниченную прокрутку;
одного результата `View`, дополненного до запрошенной высоты, может быть
недостаточно, чтобы определить конец содержимого. Встроенные wrappers
сохраняют этот контракт: `Selectable` передаёт известную высоту, а
`Collapsible` учитывает строку заголовка и сообщает высоту раскрытого
содержимого только при известной высоте inner-панели.

### Необязательные viewport-интерфейсы

```go
type ViewportRenderer interface {
    ViewAt(width, height, offset int) string
}

type ViewportElementProvider interface {
    ElementsAt(width, height, offset int) []Element
}
```

Эти необязательные интерфейсы позволяют рендерить или инспектировать
только заданную область содержимого. `Scrollable` использует их, только
если та же панель сообщает известную intrinsic-высоту через
`ContentHeightProvider`. `ViewAt` возвращает только запрошенные строки.
`ElementsAt` возвращает видимые элементы, координаты которых остаются
относительными к началу полного содержимого; затем `Scrollable` обычным
образом обрезает и сдвигает их. Без интерфейсов сохраняется прежний путь
через `View` и `Elements`.

### Необязательный Unmounter

```go
type Unmounter interface {
    Unmount()
}
```

Warp вызывает `Unmount` после отсоединения панели и удаления последней
ссылки на неё из принадлежащей владельцу иерархии. Повторные ссылки на
один экземпляр внутри одной иерархии учитываются однократно; скрытие,
сворачивание, смена фокуса и перенос панели не вызывают `Unmount`.
Реализуйте этот интерфейс на панелях-указателях, чтобы идентичность
экземпляра была стабильной. Корень `Warp` владеет всей своей иерархией;
самостоятельные `TabGroup` и `Tab` образуют отдельные иерархии. Совместное
использование одного экземпляра панели несколькими независимыми корнями
не поддерживается и должно контролироваться вызывающим кодом: глобального
учёта владения в Warp нет.

### BasePanel (структура)

` type BasePanel struct{} func (BasePanel) View(width, height int) string { return "" } func (BasePanel) Update(msg tea.Msg) tea.Cmd { return nil } `

`BasePanel` предоставляет реализацию по умолчанию без действия для
интерфейса `Panel`. Встраивайте её в конкретный тип панели и
переопределяйте только те методы, которые вам нужны, — это избавляет от
лишнего кода, сохраняя контракт интерфейса.

## Использование

Реализуйте `Panel` напрямую или встраивайте `BasePanel` для частичного
переопределения. Панель получает только те сообщения, которые пришли,
пока она находилась в фокусе.

``` go

type MyPanel struct {
    BasePanel // встраивание для значений по умолчанию
    title string
}

func (p *MyPanel) View(width, height int) string {
    return fmt.Sprintf("[%s]", p.title)
}

func (p *MyPanel) Update(msg tea.Msg) tea.Cmd {
    // обрабатываем клавиши при фокусе
    return nil
}
```

## Заметки о реализации

- **Маршрутизация сообщений** — только сфокусированные панели получают
  вызовы `Update`; неактивные панели не получают входящих сообщений.
- **Учёт размеров при отрисовке** — метод `View` получает явные `width`
  и `height`, поэтому панели могут адаптировать свою раскладку под
  доступное пространство без обращения к глобальному состоянию.
- **Встраивание (embedding)** — встраивание структур в Go даёт чистый
  путь композиции: встраивайте `BasePanel` для получения поведения по
  умолчанию и переопределяйте только то, что нужно.
- **Интеграция с Bubbletea** — интерфейс зеркалит контракт `Model` из
  `github.com/charmbracelet/bubbletea` (конкретно пару `View`/`Update`),
  что делает панели полностью совместимыми с циклом обновления
  фреймворка.
