# Движок компоновки

`layout.go` строит внутреннее дерево компоновки с координатами в ячейках на основе дерева панелей `Node` и заданного экранного прямоугольника. Полученное дерево используется для поиска панелей, сбора элементов панелей, определения перетаскиваемых границ и уведомления панелей об изменении выделенных им размеров.

Функции и структуры дерева, объявленные в этом файле, доступны только внутри пакета. Реализация работает с открытыми типами, объявленными в других файлах `warp`, включая `Node`, `SplitConfig`, `FlexConfig`, `Direction`, `Bounds`, `Element`, `BorderHit` и `ResizeMsg`.

## Модель компоновки

Входные данные — рекурсивное дерево значений `Node`:

- Узел-лист содержит `Panel` и не содержит ни `Split`, ни `Flex`.
- Узел-разделитель имеет `SplitConfig` с двумя дочерними узлами и делит свой прямоугольник в одном направлении.
- Гибкий узел имеет `FlexConfig` с упорядоченным списком элементов и распределяет между ними свой прямоугольник.

Все прямоугольники заданы в ячейках терминала. Начало координат находится в левом верхнем углу `(x, y)`; ширина и высота неотрицательны. Граница занимает одну ячейку между соседними видимыми областями и не входит в прямоугольник, выделенный ни одному из дочерних узлов.

`Direction` определён в `split.go`:

| Значение | Геометрия |
| --- | --- |
| `Vertical` | Рядом, слева направо; делится ширина. |
| `Horizontal` | Друг под другом, сверху вниз; делится высота. |

## Открытые типы, используемые этой реализацией

| Тип | Роль в компоновке |
| --- | --- |
| `Node` | Лист панели или внутренний узел-разделитель/гибкий узел. Способ обработки определяется `IsLeaf`, `IsCollapsed` и `CollapsedSize`. |
| `SplitConfig` | Задаёт направление разделения, долю, первого и второго потомка, а также состояние перетаскивания/сворачивания. |
| `FlexConfig` | Задаёт направление гибкой компоновки и упорядоченный список `Items`. |
| `FlexItem` | Содержит узел, вес `Grow`, `Basis` и состояние сворачивания. В настоящее время `Shrink` не используется для распределения размеров в flex-компоновке. |
| `Bounds` | Открытый прямоугольник с координатами ячеек `X`, `Y`, `W` и `H`. |
| `BorderHit` | Описывает границу разделителя или гибкой компоновки, её положение и длину, содержащие её границы, а также индекс элемента flex, если применимо. |
| `Element` | Элемент интерфейса, предоставленный панелью, с границами; компоновка смещает его локальные границы в экранные координаты. |
| `ResizeMsg` | Передаёт выделенные панели-листу ширину и высоту. |

`MinPanelSize` определён в `split.go` и равен 3 ячейкам; его используют вызываемые здесь вспомогательные функции расчёта размеров для разделителей и гибкой компоновки.

## Внутренние структуры данных

- `layoutRect` хранит внутренний прямоугольник (`x`, `y`, `w`, `h`) и преобразует его в открытый тип `Bounds` с помощью `toBounds`.
- `layoutNode` хранит соответствующий входной узел, выделенный ему прямоугольник, дочерние узлы после компоновки и принадлежащие этому уровню границы.

Эти типы остаются внутренними; обычно вызывающий код взаимодействует с компоновкой через более высокоуровневые операции отрисовки, проверки попаданий и работы с вкладками.

## Построение компоновки

`newLayout(node, bounds)` ограничивает ширину и высоту снизу нулём, а затем рекурсивно строит компоновку. При nil-узле или узле-листе рекурсия сразу завершается. Для внутренних узлов сначала обрабатывается ненулевой `split`; иначе раскладывается ненулевой `flex`. У узла, у которого нет подходящей конфигурации, дочерних элементов не будет.

### Компоновка разделителя

`layoutSplit` выделяет место двум дочерним узлам согласно `SplitConfig.Direction`:

- При `Vertical` делится ширина, а второй дочерний узел размещается справа.
- При `Horizontal` делится высота, а второй дочерний узел размещается ниже.

Одноячеечная граница резервируется, только если оба дочерних узла не свёрнуты и размер соответствующей оси родителя положителен. Если свёрнут хотя бы один дочерний узел, граница не резервируется и не отображается. Длину оставшейся части оси ограничивают снизу нулём перед вызовом `computeSplitSizes`. Эта функция получает заданную долю, флаги сворачивания и размеры свёрнутых узлов для соответствующих направлений. Макеты обоих дочерних узлов создаются, даже если выделенные им размеры равны нулю.

Для видимой границы разделителя сохраняются `SplitConfig`, направление, экранное положение, длина поперёк оси, границы родителя и `FlexIndex: -1`.

### Гибкая компоновка

Если элементов нет, `layoutFlex` возвращает управление, не создавая дочерних узлов. Для `Vertical` гибкой компоновки выбирается ширина, в противном случае — высота. Число видимых разделителей определяется только между соседними несвёрнутыми элементами и ограничивается доступным размером оси. Это число вычитается из размера оси перед передачей оставшегося пространства в `computeFlexSizes` для распределения размеров элементов.

Элементы обрабатываются по порядку. Каждый дочерний узел получает размеры родителя по поперечной оси и выделенный ему размер по оси гибкой компоновки. Граница размещается перед элементом, только если он и непосредственно предшествующий ему элемент не свёрнуты и на оси хватает места для границы. Разделители вертикальной гибкой компоновки являются горизонтальными границами; разделители горизонтальной — вертикальными. Для каждой границы flex сохраняются `FlexConfig`, границы владельца, положение и длина, а также `FlexIndex` элемента перед разделителем. Элементы flex со значением nil считаются свёрнутыми; для них создаётся дочерний макет с nil-узлом.

Вспомогательная функция расчёта размеров flex (в `render.go`) использует базовый размер каждого элемента: неположительный `Basis` считается равным `MinPanelSize`, а базовый размер свёрнутого элемента — 1. Если сумма базовых размеров превышает доступное пространство, базовые размеры пропорционально уменьшаются. Иначе оставшееся пространство распределяется между несвёрнутыми элементами пропорционально положительным весам `Grow`; если положительного веса `Grow` нет ни у одного элемента, пространство распределяется равномерно. `Shrink` не используется. Округлением целых чисел занимается функция расчёта размеров.

## Запросы и обход результатов

### Границы

`collectLayoutBorders` собирает границы в прямом обходе в глубину: границы узла добавляются раньше границ его дочерних узлов. `appendLayoutBorders` допускает nil-макеты. Записи о границах разделителей и flex можно различить по тому, заполнено ли поле `BorderHit.Split` или `BorderHit.Flex`.

### Поиск flex

`findFlexLayout` рекурсивно ищет первый макет, узел которого ссылается на запрошенный `FlexConfig` по идентичности. Если макет равен nil или конфигурация не найдена, возвращается nil.

### Проверка попадания в панель

`findLayoutPanel(layout, x, y)` сначала проверяет, находится ли координата внутри текущего прямоугольника, используя полуоткрытые границы: левая и верхняя стороны включены, правая и нижняя — исключены. Если соответствующий узел является листом, функция возвращает `panelHit` с этим узлом и выделенным ему прямоугольником. В противном случае она по порядку проверяет дочерние узлы и возвращает первое попадание. Для nil-макетов, точек за пределами макета и незанятых областей (например, границ) возвращается nil.

### Элементы

`elementsFromLayout` обходит дерево и возвращает элементы только для узлов-листьев. Для каждого листа `elementsAtLayout` вызывает `collectElements`, передавая панель и её локальные выделенные ширину и высоту, клонирует возвращённые элементы и смещает границы каждого элемента на экранное начало координат листа. Также смещаются вложенные дочерние элементы. Таким образом, возвращаемая геометрия задана относительно экрана, а поставщики элементов получают локальные для панели размеры. Для nil-макетов и nil-узлов элементы не возвращаются.

### Уведомления об изменении размера

`(*Tab).broadcastLayoutResize` обходит макет и накапливает ненулевые значения Bubble Tea `tea.Cmd`, возвращённые при обновлении панелей. `appendLayoutResize` отправляет каждому ненулевому panel в листе сообщение `ResizeMsg{Width, Height}` с выделенными этому листу размерами содержимого. Внутренние узлы рекурсивно обходятся по дочерним узлам; nil-макеты и nil-узлы пропускаются. Метод не отправляет сообщения об изменении размера внутренним узлам или границам.

## Примечания по реализации

- Геометрия и проверки попаданий используют целые числа ячеек терминала, а не пиксели.
- Отрицательные запрошенные размеры при создании макета нормализуются до нуля. Ширина и высота дочерних узлов также защищены от отрицательных значений при назначении.
- У границ есть собственная геометрия для определения попаданий, но они занимают ячейку за пределами прямоугольников обоих соседних дочерних узлов.
- Состояние сворачивания влияет на видимость границы разделителя и расчёт его размеров; сворачивание элемента flex влияет на видимость разделителя и базовый размер этого элемента при flex-компоновке.
- Эти вспомогательные функции не изменяют входное дерево панелей. Они создают отдельное дерево компоновки, в котором сохраняются прямоугольники для последующих запросов и сообщений об изменении размера.
- Bubble Tea импортируется в этот файл только для использования `tea.Cmd` в командах, возвращаемых при обновлении панелей.
