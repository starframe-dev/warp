# Warp

`Warp` — корневая модель TUI-приложения Bubbletea. Она оборачивает
произвольную корневую `Panel` (по умолчанию — `TabGroup` с одной
вкладкой) и передаёт каждое входящее сообщение напрямую этой панели без
перехвата.

Помимо того что является моделью Bubbletea (`Init`, `Update`, `View`),
`Warp` предоставляет:

- Удобные методы для вкладок, делегирующие в корневую `TabGroup`, когда
  она таковой.
- Необязательный HTTP-сервер для просмотра живого дерева элементов
  извне.
- Адаптер `Panel` (`AsPanel`), позволяющий встроить `Warp` в другую
  панель или другой `Warp`.

## Публичный API

### Создание

` w := warp.New() `

`New` возвращает `*Warp`, чей корень — свежий `TabGroup` с положением
`TabTop` и одной владкой по умолчанию. Модель безопасна для
использования сразу после создания.

### Доступ к корневой панели

` func (w *Warp) SetRoot(panel Panel) func (w *Warp) Root() Panel `

`SetRoot` заменяет корневую панель — установите сплиты, flex-контейнеры,
вложенные группировки вкладок или любую другую реализацию `Panel`.
`Root` возвращает текущую установленную панель.

### Доступ к размерам

` func (w *Warp) Width() int func (w *Warp) Height() int `

Возвращают последний известный размер терминала. Эти значения
обновляются из `tea.WindowSizeMsg` во время `Update` и используются
`View` и HTTP-эндпоинтом при рендеринге.

### Делегирование вкладок

` func (w *Warp) NewTab(name string) *Tab func (w *Warp) ActiveTab() *Tab func (w *Warp) SetTabPosition(pos TabPosition) func (w *Warp) NextTab() func (w *Warp) PrevTab() `

Это чисто удобные делегаты: если корневая панель — `*TabGroup`, они
передают в неё; в противном случае они no-op (возвращают `nil` там, где
ожидается значение). Они существуют, чтобы вызывающие не нуждались в
downcast корня.

### Встраивание как панель

` func (w *Warp) AsPanel() Panel `

Возвращает адаптер `warpPanel`, реализующий интерфейс `Panel` (т.е.
`View(width, height)` и `Update(msg)`). Именно так `Warp` может быть
вложен в другую панель или другой `Warp`.

### Жизненный цикл

` func (w *Warp) Run() error `

Запускает программу Bubbletea (alt-screen + клеточное движение мыши) и
блокируется до выхода программы. Возвращаемая ошибка — ошибка выхода
программы.

### HTTP-сервер

` func (w *Warp) ServeHTTP(addr string) error func (w *Warp) CloseHTTP() error func (w *Warp) HTTPAddr() string `

`ServeHTTP` запускает одно-подключаемый HTTP-сервер на `addr` (или
переменную окружения `WARP_HTTP_PORT`, или `:0` для случайного порта
если пусто), открывая два эндпоинта:

| Путь | Описание |
|----|----|
| `/elements` | JSON-массив отрендеренного в данный момент дерева элементов при текущем (или резервном 80x24) размере |
| `/healthz` | Plain-text `ok` health-зонд |

Сервер идемпотентен при запуске (второй вызов во время работы — no-op) и
идеемпотентен при закрытии. `HTTPAddr` возвращает привязанный адрес или
пустую строку, когда сервер не работает.

## Модель Bubbletea

` func (w *Warp) Init() tea.Cmd func (w *Warp) Update(msg tea.Msg) (tea.Model, tea.Cmd) func (w *Warp) View() string `

`Init` возвращает `nil`. `Update` перехватывает только
`tea.WindowSizeMsg`, чтобы записать размеры окна, затем передаёт каждое
сообщение (включая сообщение о размере) в `w.root.Update`. Если корневая
панель — `nil`, `Update` возвращает пустую команду.

`View` рендерит `w.root.View(width, height)`. Если размер ещё не
известен (0x0), отображается строка-заглушка `Loading...`; если корень —
`nil`, отображается пустая строка.

## Вложенность

Поскольку `AsPanel` предоставляет интерфейс `Panel`, `Warp` можно
поместить в другую панель (или другой `Warp`). Адаптерный `View`
записывает размеры, предоставленные родительным, обратно во вложенный
`Warp` и затем рендерит его корень, тогда как `Update` просто передаёт
сообщение и возвращает полученную команду.

``` go
parent := warp.New()
inner  := warp.New()
parent.SetRoot(inner.AsPanel()) // inner Warp embedded in parent
```

## Заметки о реализации

- `httpMu` сериализует доступ к полям HTTP-сервера и также реентернентно
  удерживается, пока `handleElements` снимает снимок `width`, `height` и
  `root`. Обработчик `/elements` поэтому рендерит дерево вне блокировки,
  удерживая её только для публикации JSON.
- HTTP-сервер намеренно минималистский: он привязывает один
  `net.Listener`, подаёт два обработчика mux и никогда не
  пере-привязывает. Двойной вызов `ServeHTTP` (до закрытия первого)
  возвращает `nil` и сохраняет исходный listener.
- Ответ дерева элементов всегда сериализуется как JSON-массив; если
  корень — `nil`, это пустой массив (не `null`).
- `parsePort` — внутренний помощник для извлечения привязанного порта;
  он намеренно не экспортируется.
