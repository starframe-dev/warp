# Warp

`Warp` — корневая модель TUI-приложения Bubble Tea. Она оборачивает произвольную корневую панель `Panel` (по умолчанию — `TabGroup` с одной вкладкой), записывает входящие размеры окна и передаёт сообщения этой панели.

Помимо реализации модели Bubble Tea (`Init`, `Update`, `View`), `Warp` предоставляет:

- Удобные методы для работы с вкладками, делегирующие вызовы корневой `TabGroup`, если она установлена.
- Возможность запустить HTTP-сервер для внешнего просмотра последнего снимка элементов, сделанного в UI-потоке.
- Адаптер `Panel` (`AsPanel`), позволяющий встроить `Warp` в другую панель или другой `Warp`.

## Публичный API

### Создание

`w := warp.New()`

`New` возвращает `*Warp` с новой корневой `TabGroup`, расположенной в позиции `TabTop` и содержащей одну вкладку по умолчанию. Модель можно безопасно использовать сразу после создания.

### Доступ к корневой панели

```go
func (w *Warp) SetRoot(panel Panel)
func (w *Warp) Root() Panel
```

`SetRoot` заменяет корневую панель: можно установить разделения, flex-контейнеры, вложенные группы вкладок или любую другую реализацию `Panel`. `Root` возвращает текущую установленную панель.

### Получение размеров

```go
func (w *Warp) Width() int
func (w *Warp) Height() int
```

Возвращают последние известные размеры терминала. Они обновляются из `tea.WindowSizeMsg` в `Update` или из размеров, переданных в `AsPanel().View`, если Warp встроен в другую панель. `View` использует их для отображения корневой панели, а UI-поток — для построения HTTP-снимка элементов.

### Делегирование методов вкладок

```go
func (w *Warp) NewTab(name string) *Tab
func (w *Warp) ActiveTab() *Tab
func (w *Warp) SetTabPosition(pos TabPosition)
func (w *Warp) NextTab()
func (w *Warp) PrevTab()
```

Это исключительно удобные методы-делегаты: если корневая панель — `*TabGroup`, вызовы передаются ей; в противном случае методы ничего не делают (а там, где ожидается значение, возвращают `nil`). Они избавляют вызывающий код от необходимости приводить корневую панель к конкретному типу.

### Встраивание в качестве панели

`func (w *Warp) AsPanel() Panel`

Возвращает адаптер `warpPanel`, реализующий интерфейс `Panel` (то есть `View(width, height)` и `Update(msg)`). Так `Warp` можно вложить в другую панель или другой `Warp`.

### Жизненный цикл

```go
func (w *Warp) Run() error
func (w *Warp) Close() error
```

`Run` запускает программу Bubble Tea (alt-screen и отслеживание движения мыши по ячейкам терминала) и блокируется до её завершения. `Close` останавливает HTTP-инспектор и, если Warp является корневым, отсоединяет принадлежащую ему иерархию панелей, освобождая уникальные панели с `Unmounter`. `Close` идемпотентен; его рекомендуется вызывать во вложенных сценариях и долгоживущих процессах.

### Безопасность терминального текста

Метки, принадлежащие фреймворку, считаются метаданными, а не терминальными потоками. Warp отображает названия вкладок, заголовки float/collapsible, метки и варианты dropdown, подсказки ввода, заголовки и кнопки модальных окон, а также названия элементов popover как обычный безопасный для терминала текст. Из таких меток удаляются последовательности ANSI/OSC, некорректный UTF-8 нормализуется, а управляющие символы разметки не могут поглотить окружающие элементы интерфейса фреймворка. Произвольный вывод `Panel.View` и `Modal.Content` по-прежнему может содержать ANSI-последовательности.

### Владение ресурсами панелей

Корневой `Warp` владеет всей иерархией панелей, включая вложенные вкладки, обёртки и плавающие панели. Самостоятельные `TabGroup` или `Tab` владеют отдельной иерархией, пока не встроены в другого владельца. Панели, реализующие `Unmounter`, размонтируются один раз после отсоединения и исчезновения из иерархии этого владельца. Скрытие, сворачивание, смена фокуса и перемещение между родителями не приводят к размонтированию. Для панелей, основанных на указателях, используется идентичность экземпляра; совместное использование одного экземпляра панели между независимыми корнями `Warp` не поддерживается и остаётся ответственностью вызывающего кода. Warp не ведёт глобальный реестр владения.

### HTTP-сервер

```go
type InspectorOptions struct {
    AllowedOrigin string
    BearerToken   string
}

func (w *Warp) ServeHTTP(addr string) error
func (w *Warp) ServeHTTPWithOptions(addr string, options InspectorOptions) error
func (w *Warp) CloseHTTP() error
func (w *Warp) HTTPAddr() string
```

`ServeHTTP` запускает HTTP-сервер по адресу `addr` и предоставляет два эндпоинта. Если `addr` пуст, сервер привязывается к `127.0.0.1` на порту из `WARP_HTTP_PORT` либо на автоматически назначенном порту, если эта переменная не задана. Непустой адрес используется без изменений. Межсайтовый доступ по умолчанию отключён. `ServeHTTPWithOptions` позволяет явно разрешить точный CORS origin (или указать `"*"`) и потребовать bearer token для `/elements`.

| Путь | Описание |
|----|----|
| `/elements` | JSON-массив из последнего завершённого снимка UI-потока (строится для текущего размера или для 80×24, если размеры неизвестны) |
| `/healthz` | Текстовый ответ `ok` для проверки работоспособности |

Повторный запуск уже работающего сервера ничего не меняет; закрытие также идемпотентно. `HTTPAddr` возвращает адрес привязки или пустую строку, если сервер не запущен.

## Модель Bubble Tea

```go
func (w *Warp) Init() tea.Cmd
func (w *Warp) Update(msg tea.Msg) (tea.Model, tea.Cmd)
func (w *Warp) View() string
```

`Init` возвращает `nil`. `Update` перехватывает только `tea.WindowSizeMsg`, чтобы записать размеры окна, а затем передаёт каждое сообщение (включая сообщение о размере) в `w.root.Update`. Если корневая панель равна `nil`, `Update` не возвращает команду. При включённом HTTP-инспекторе обычные сообщения приводят к публикации нового семантического снимка после `Update`. Сообщение, реализующее `SemanticStableMsg` и возвращающее `true`, явно разрешает повторно использовать предыдущий снимок до следующего `View`.

`View` отображает `w.root.View(width, height)`. Если хотя бы один размер ещё неизвестен (равен нулю), возвращается строка-заполнитель `Loading...`; если корень равен `nil`, возвращается пустая строка. После отображения снимок элементов обновляется.

## Вложенность

Поскольку `AsPanel` предоставляет интерфейс `Panel`, `Warp` можно поместить внутрь другой панели (или другого `Warp`). Метод `View` адаптера записывает переданные родителем размеры во вложенный `Warp`, а затем отображает его корневую панель; `Update` просто передаёт сообщение и возвращает полученную команду.

```go
parent := warp.New()
inner  := warp.New()
parent.SetRoot(inner.AsPanel()) // inner Warp embedded in parent
```

## Примечания по реализации

- После каждого `Update` UI-поток собирает элементы и глубоко копирует их `Children`, прежде чем публиковать неизменяемый снимок, если только сообщение не реализует `SemanticStableMsg` и не возвращает `true`; в этом случае предыдущий снимок используется повторно до следующего `View`. После каждого завершённого `View` элементы собираются и копируются, если инспектор включён. Обновление после `View` выполняется намеренно: пользовательские панели могут менять семантическое состояние во время отображения. Сбор элементов вызывает `Panel.Elements` без удержания mutex Warp.
- `/elements` читает только последний завершённый снимок. Он никогда не обходит живое дерево панелей и не вызывает `Panel.Elements`, `Panel.View` или `Panel.Update`; ответ может отставать на одну UI-операцию, но не может содержать данные частично обновлённого дерева.
- Ревизия корня не позволяет опубликовать снимок, собранный для старого корня, после `SetRoot`. `SetRoot` также сразу инвалидирует уже опубликованный снимок, поэтому `/elements` не может показать отсоединённую иерархию до следующего цикла UI. Снимок или корень со значением `nil` сериализуется как пустой JSON-массив, а не `null`.
- Если при построении снимка размеры неизвестны, инспектор использует 80×24.
- Пока HTTP-сервер работает, повторный запуск идемпотентен. `CloseHTTP` отсоединяет сервер под mutex, а затем вызывает `http.Server.Shutdown`, не удерживая этот mutex.
